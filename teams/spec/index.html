1approval for Teams オプション 基本仕様書

Microsoft Teamsをフロントエンド対話インターフェースとして既存承認ワークフローに寄生統合するシステム拡張仕様

1. システム概要・目的

1.1 システム概要

本システム「1approval for Teams オプション」は、企業で広く利用されているコミュニケーションツール「Microsoft Teams」上で、対話（チャットボット）形式により出張手配申請および承認・購買手続きを完結させるフロントエンド統合拡張機能である。

既存のワークフローシステム（Microsoft 365 SharePoint、kintone、x-point / AgileWorks等）をリプレイスすることなくその上にかぶせて接続（寄生）し、中間統合OS「1approval Hub」を介して購買ポータル（ピカパカ出張DX等）と双方向連携させる。

1.2 主な解決課題と提供価値

① 二重入力・二重承認の排除

チャットボットとの対話で基本情報を入力し、購買サイトからパンチアウト連携することで手配・手動転記の手間を消去。

② 申請手戻り・再承認の防止

承認タイムラグによる宿泊・交通の価格変動を「ダイナミック・ポリシー」で自動吸収し手戻りを防止。

③ 個人立替・領収書管理ゼロ

上長承認と同時に全自動予約が完結。会社への月1回・1枚の法人一括請求に集約し経費精算を不要化。

No. ボットの質問メッセージ UI / 入力形式 処理・動作仕様

1-4 出張目的を入力してください。 フリーテキスト（長文可） 例: 「福岡のクライアントに会って現地商談を行うため」
1-5 出張期間を入力してください。 カレンダー（日付範囲選択） 出発日・帰着日を同時に選択

2 Block 2: スケジュール ＆ 一時下書き自動起票

No. ボットの質問メッセージ UI / 入力形式 処理・動作仕様
2-1 【1日目】訪問先を入力してください。 フリーテキスト 例: 「株式会社岩田屋三越」
2-2 その日の目的・用件を入力してください。 フリーテキスト 例: 「出張支援SaaSの訪問提案」
【重要仕様：自動下書き起票 trigger】 ユーザーが Block 2-2 の入力を完了して送信したタイミングで、1approval HubはバックエンドWF（SharePoint / kintone）に対し、入力済みの「基本情報＋スケジュール」レコードを「下書き（未申請）」として自動送信・即時保存する。

3 Block 3: 手配選択・パンチイン / パンチアウト・手配確定ループ

Step 3-A/B: パンチイン移動 ＆ 商品選択

手配ボタン（例: [🏨 ホテル]）を押すとSSOトークン付きURLを発行し、パンチインで「ピカパカ出張DX」の手配画面を開く。

Step 3-C/D: パンチアウト戻り ＆ 確定

ピカパカの「申請ワークフローに戻す」を押すと、カート情報（cXML）が引き渡されTeams上で確認カードを表示。確定ボタンで申請書へ自動追記。

URL自動パース（Fallback機構）＆ API連携の補意 パンチアウト未対応のサイトや手配方式の場合でも、ピカパカ出張DX等から取得した該当商品URLをTeamsチャットにペーストすると、1approval Hubのパースエンジンが自動で施設名・価格・利用日を取り込みます。取り込まれたデータはx-point（`AddComment` / 書類編集API）やAgileWorks (フォーム更新API)経由で自動申請登録されます。

4 Block 4: 手配終了 ＆ 申請書確認・承認依頼

[手配を終了して申請書を見る] を選択すると、ボットがSharePoint/kintone上の申請書へのダイレクトリンクを出力。ユーザーはリンク先で最終確認を行い、ステータスを「承認依頼をする」に変更。上長承認が完了した瞬間、裏側で即時予約・発注APIが実行されます。

5 Block 5: 事後証票（領収書）回収 ＆ AI-OCR自動照合フロー

現地決済やタクシー・小口購入等の立替費用、および証票添付が必要な購買項目に対し、Teamsチャット上で直接画像・PDFを添付・提出することで証票回収を完結します。

No. ボットの案内メッセージ UI / アクション 処理・動作仕様

5. ガバナンス・機能要件

5.1 ダイナミック・ポリシー機能

申請から上長承認までのタイムラグ間に発生する宿泊・航空券の価格変動（ダイナミックプライシング）を自動吸収。企業ごとに設定した許容変動割合（例: 20%）の範囲内であれば再承認なしで即時自動予約。超えた場合は自動差戻し。

5.2 Level 3 Data ＆ Peppol対応

「誰が・いつ・どの施設/区間を・いくらで（品目・数量・単価）」という完全な購買明細（Level 3データ）をcXML/Peppol（JP PINT）形式で保持。月末に月1回の電子請求書として勘定奉行・楽楽精算・Concur等へ自動仕訳連携。

5.3 証票（領収書）回収 ＆ AI-OCR自動照合

Teamsチャット上に送信された領収書画像（JPG/PNG/PDF）をAI-OCR解析し、金額・日付・発行先を出張手配データと自動突合。電子帳簿保存法（電帳法）に準拠した形式でSharePoint/kintone/x-pointへ自律保管。

6. 非機能要件・セキュリティ

認証・認可: Microsoft Entra ID (旧 Azure AD) / OAuth 2.0 に基づくシングルサインオン（SSO）。
監査ログ: チャット対話履歴、パンチイン/パンチアウトセッション、バックエンドAPI連携ログを全件暗号化保存。
可用性・SLA: クラウドマルチリージョン構成により SLA 99.9% 以上を担保。
