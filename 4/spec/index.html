One Approval システム要件定義・基本設計書

対象：中堅・大手企業向け 統合購買・現物資産・MDM・貸出・棚卸プラットフォーム

Version 2.0.0 2026-07-30
1.1 開発目的と対象範囲

本システム「One Approval」は、年商100億〜1000億円規模の製造業・建設業等を主要ターゲットとし、既存のワークフロー（kintone）とMonotaRO（ECサイト）をシームレスに統合するとともに、購買から資産化・個体/数量管理・MDM管理・貸出予約・棚卸・修繕履歴管理までを一気通貫で自動化・可視化するミドルウェア＆Webアプリケーションです。

購買の完全統一
MonotaRO cXML自動購買とkintone手動購買申請を一元管理し、検収データをワンタップで資産化。
二重管理の解消
固定資産（個体管理）と消耗品（数量管理）を分離しつつ、セット品紐付けやQR・管理ラベル印刷に対応。
現場現場運用の効率化
カレンダー型貸出予約、スマホQRスキャン、棚卸依頼・状態報告、定期校正・修理記録を網羅。

[ MonotaRO (EC) ] <--- cXML (PunchOut/Order/ShipNotice) ---> [ One Approval Middleware ]

   ├── 📅 カレンダー貸出 ＆ QR返却

   └── 🔧 点検・校正・修理記録

2. 画面機能詳細仕様

モジュール 01 2.1 購買管理（kintone / MonotaRO）
機能概要 MonotaRO連携購買とkintone手動購買申請の統合一覧表示および「資産化（資産管理への引き継ぎ）」フローの実装。
種別判別
  • MonotaRO連携: cXML PunchOut経由で注文され、出荷通知（ShipNotice）と連携済みのデータ。
  • 手動購買: 他社Webサイトや型番指定でkintoneアプリから手動申請・承認された購買データ。
資産化アクション ステータスが「検収済」の明細に対して「資産化（資産管理へ登録）」ボタンを設置。
モーダル画面にて【個体管理（固定資産・備品）】または【数量管理（消耗品）】を選択し、資産台帳レコードを自動生成する。
ステータス遷移 申請中 → 承認済（発注完了） → 出荷済 → 検収済 → 資産化完了
モジュール 02 2.2 資産管理（個体・数量・セット品）
管理形態の分離
  • 個体管理（固定資産・機器）: 1点ごとに固有の管理番号（AST-XXXX）、シリアルNo、写真を保持。貸出・点検の対象。
  • 数量管理（消耗品・パーツ）: 品目単位で総在庫数を保持。「ピックアップ（出庫）」ボタンで即座に数量減算処理を実行。
詳細・附属機能
  • セット備品紐付け: 例「一眼レフカメラ本体」に対し「交換レンズ」「三脚」「専用ケース」を親子の関連備品としてバインド管理。
  • 管理ラベル / QRコード発行: 管理番号・QRコード・名称を含むラベル印刷用PDF/SVGのリアルタイム生成機能。
  • 関連ファイル一体管理: 取扱説明書(PDF)、保証書(画像)、見積・仕様書などをレコードに添付。
  • 変更履歴ログ: 誰が・いつ・どの項目（ステータス・保管場所・数量など）を変更したかを自動記録。
モジュール 03 2.3 MDM管理（IT資産・モバイル）

資産管理上の固定資産（PC・スマホ・タブレット等）から「MDM管理へ回す」フラグをオンにすることで移行される高機能IT資産画面です。

  • 管理項目: OSバージョン、CPU、RAM、ストレージ容量、MACアドレス、IMEI、携帯キャリア契約情報。
  • 契約・期限管理: リース/レンタル満了日、メーカー保証期限、ソフトウェアライセンス更新日。
  • アラート通知機能: 契約満了の30日前・60日前に管理者および利用担当者へメール/Teams/Slack自動通知。
モジュール 04 2.4 貸出管理（カレンダー・QR・アラート）
📅 カレンダー予約・検索

個体管理されている固定資産の空き状況をカレンダー上でリアルタイム確認し、「誰が・いつから・いつまで」利用するかをドラッグ＆ドロップで事前予約。

📱 QRコード貸出・返却 ＆ 返却アラート

現場のスマホ/タブレットカメラで管理ラベルのQRコードを読み取り、ワンタップで即時貸出/返却。返却予定日時を過ぎた場合は自動アラートメールを配信。

モジュール 05 2.5 棚卸機能（依頼・実地報告）
棚卸依頼の起案 管理者が対象範囲（拠点・部署・カテゴリ：消耗品/固定資産/MDM）と期日を指定して「棚卸タスク」を一括発行。
実地報告UI 各拠点・現場の担当者はスマホ等で対象備品を確認し、以下の状態を選択して報告：
正常 要修理 破損・故障 紛失
消耗品の場合は、実測の「現在実在庫数」を入力して理論在庫との差異を自動計算。
モジュール 06 2.6 点検修理記録

固定資産およびMDM管理物品に対し、法定制期点検・機器校正（キャリブレーション）・故障修理の履歴をログ保持します。

  • 点検・校正周期管理: 次回点検予定日を設定し、期日が近づいた機器の貸出制限または通知を実行。
  • 記録項目: 実施日、業者名、費用、点検結果、校正証明書PDFの添付。
モジュール 07 2.7 メンバー・権限管理

全社ユーザーの所属部署、役職、および本システムでのアクセス権限（ロール）を管理します。

（ロール定義：システム管理者 / 購買・経理担当 / 資産管理者 / 一般現場社員）

4. 外部連携・シーケンス

4.1 MonotaRO PunchOut (cXML) 通信フロー
  1. PunchOutSetupRequest: ユーザーが「MonotaROで商品を探す」をクリック時、One ApprovalからMonotaROへワンタイムURLを要求。
  2. PunchOutOrderMessage: MonotaROのカゴ入れ完了後、カート情報（SKU・単価・数量）がcXMLでOne Approvalに返却。
  3. kintone PO Sync: 送信されたカート情報を元にkintoneワークフローアプリへ自動申請レコードを生成。
  4. OrderRequest: kintoneで最終承認されたタイミングで、One ApprovalからMonotaROへ確定注文cXMLを送信。
