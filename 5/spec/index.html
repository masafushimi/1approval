1.1 1approval Core のコンセプト

「あらゆる承認と、それに伴う購買・支出・リソース移動を単一ハブで統合制御する企業の中枢神経系」

1approvalは、企業内に乱立するワークフローシステム（kintone, Garoon, Salesforce, Agileworks等）と各種EC/調達プラットフォーム（MonotaRO, Amazon Business, エイチ, 団タメ等）、さらには現地立替精算をシームレスに中継します。

通過するデータを標準化されたL3データ（Who / What / When / Where / Why）として蓄積し、Peppol電子請求・インボイス対応の基盤化、サプライヤー契約のデジタル締結、AIによる不正・異常検知、および法人請求・立替精算の自動会計ルーティングを実現します。

2. 中核機能プラットフォーム

中核 01 2.1 連携セットアップ (Flowbuilder) ＆ サプライヤー契約オンボーディング

接続先システム同士のフロー設計（Flowbuilder）と、新規購買チャネル開設時のサプライヤー自動契約（デジタル締結）を一元化されたUIで処理します。

サプライヤー管理 ＆ 自動契約締結機能
機能概要 顧客企業が新規購買システム（EC・サービス）を利用開始する際、1approval画面上で標準約款・雛形に基づく契約締結をデジタル完結する機能。
自動オンボーディング
  • 標準契約雛形（規約同意）: 1approvalが用意した基本契約雛形に対し、ワンタップで電子同意・締結処理を完了。
  • 自動ノード解放: 契約締結が成功した瞬間、Flowbuilder上の該当サプライヤー（例: 団タメ、ピカパカ等）の連携ノードがアクティブ化し、フローに組込可能となる。
  • 個別の特約/独自契約対応: 雛形に合意できない例外ケースの場合、個別契約書PDFアップロードおよび承認ステータス管理機能へ自動分岐。
ビジュアルフロービルダー (Flowbuilder)
キャンバス機能 「申請元のWF」→「契約済みサプライヤー」→「後続の会計/経費システム」をドラッグ＆ドロップで結線。各ノード間で配送先・請求先マスタのデータ自動補完ロジックを適用。
接続対応ターゲット
  • 承認WF: kintone, Garoon, サイボウズ, Salesforce, M365, Agileworks, x-point, コラボフロー 等
  • 購買・サービス: モノタロウ, Amazon Business, ピカパカ, ビズバンス, NetRICOH, オレンジブック, エイチ(会議室), 団タメ(宴会・会食) 等
中核 02 2.2 組織・人事・承認権限 Sync

各外部ツールで分断しがちなマスターデータを1approvalをハブとして双方向同期（Sync）します。

  • 従業員データ・組織階層: SmartHRやEntra ID(Azure AD)等を元に、部署・役職・上位組織階層を自動取り込み。
  • 承認フロー定義の集中同期: 1approval側で設定した承認権限マスタ（例: 50万円以上は事業部長承認）を各接続先WFへ配信。
中核 03 2.3 L3データ蓄積・仕訳ルーティング

将来的なPeppol電子請求・デジタルインボイス・電帳法に対応するため、すべての取引を高度なL3データへ統一・正規化します。

L3要素保持データ項目用途
WHO申請者ID、所属部署、承認者チェーン、予算オーナー監査トレース、費用負担部署特定
WHATSKU明細、品目名、単価、数量、税区分(10%/8%/軽減)デジタルインボイス(Peppol)、仕訳自動化
WHEN申請日、承認完了日、発注日時、検収確認日期末決算処理、未払計上コントロール
WHERE購買チャネル(Amazon/モノタロウ/現地等)、店舗コードチャネル別支出分析、相場比較
WHY勘定科目、プロジェクトコード、申請目的理由予実管理、ガバナンスルールチェック
自動決済ルーティング処理
  • 法人請求（売掛・請求書）: 会計システム（勘定奉行等）へ買掛金・自動仕訳データとして送出。
  • 個人立替（現金・個クレ）: 経費精算システム（楽楽精算等）へ立替精算申請データとして送出。
中核 04 2.4 統合支出・購買・予実制御

ECサイトでの購買、専門サービスの予約、現場の現地立替経費を同一画面で一元管理・見える化します。

  • リアルタイム予実管理: 部署・プロジェクト単位で月次・年次予算を設定。発注・申請時点で消化額をリアルタイム計算。
  • 予算オーバー自動制御: 予算超過が発生した場合、承認申請を強制ロック（エラー表示）または特別承認ルート（役員承認）へ自動変更。
中核 05 2.5 ガバナンス・不正・異常検知エンジン

支出データに対してAI・ルールベースによる継続的モニタリングを実施し、コスト削減ポテンシャルと規程違反を自動抽出します。

相場異常値チェック
同等品SKUや過去実績・市場相場と比較し、一定倍率以上の割高購入や不正な高額経費を即座にアラート表示。
重複申請チェック
同日・同金額・同一領収書画像・類似品目の二重申請（立替経費と法人カードの重複など）を自動検知。
社内規程逸脱チェック
「新幹線グリーン車利用」「交際費の上限オーバー」「事前申請なしの事後精算」などの規程違反を自動判定。
中核 06 2.6 レポーティング ＆ BIアナリティクス

経営層および管理部門向けに、以下の標準レポートBIダッシュボードを標準提供します。

経費精算サマリーBI: 月次の支出動向・部署別推移
異常値発見レポート: 相場逸脱・不正疑いの集計
重複発見レポート: 二重申請の検出フラグ一覧
交際費レポート: 参加者・単価・税法上限チェック
出張者一覧レポート (週次): 出張予定・実績の一覧
駐在員連絡機能: 現地駐在員への出張者情報自動配信

3. 現場・資産運用機能

現場 01 3.1 統合資産台帳（個体・数量・親子セット備品）

検収されたL3購買データからワンタップで資産登録。個体・数量・親子構成管理をサポートします。

個体管理 (Fixed Assets) PC、車両、機器など管理番号（AST-XXXX）やシリアルNoを個別に付与。写真・取扱説明書(PDF)・保証書画像・仕様書を一体管理。QRラベル（PDF/SVG）の即時印刷に対応。
数量管理 (Consumables) オフィス用品、パーツ類など品目ごとの総在庫数を管理。「出庫（ピックアップ）」で即時減算。安全在庫閾値未満で自動補充購入フロー（Flowbuilder）を発火。
親子セット備品 (Bundle) 「一眼レフカメラ本体（親）」に対し「交換レンズ」「三脚」「専用ケース（子）」を親子関係（parent_asset_id）としてバインド管理。一括貸出・一括棚卸に対応。
現場 02 3.2 MDM・IT資産 ＆ 契約期限アラート

IT資産（PC、スマホ、タブレット）のスペック情報（OS, CPU, RAM, MACアドレス, IMEI, キャリア契約）をMDM（Intune / Jamf Pro）とAPI連携。

  • 契約・期限アラート通知: リース/レンタル満了日、メーカー保証期限、ライセンス更新の30日前・60日前に管理者および利用者へメール/Teams/Slack自動通知。
  • 退職・移動時の即時ロック: 人事Sync機能と連動し、退職日をもって端末の遠隔ロック・ワイプ（初期化）命令を発行。
現場 03 3.3 カレンダー型貸出予約 ＆ モバイル実地棚卸
カレンダー型貸出予約・返却管理

共有備品の空き状況をカレンダー上で確認し、ドラッグ＆ドロップで事前予約。スマホQRスキャンで即時貸出/返却処理。返却遅延者へ催促アラートを配信。

スマホカメラによる現場リアルタイム棚卸

管理者が発行した棚卸タスクに基づき、現場担当者がPWA/スマホカメラでQRをスキャンして実地報告。

  • 明確な状態区分報告: スキャン時に状態を【正常】【要修理】【破損・故障】【紛失】の4区分から選択。写真・コメントを添付可能。
  • オフライン同期: 電波の届かない地下倉庫や現場でもローカルストレージに保持し、通信復帰時に一括同期。差異（理論在庫とのズレ）を自動計算。

4. データモデル・API仕様

Data 01 4.1 L3 Ledger ＆ 資産管理データベース構造

L3購買取引データおよび親子バインド資産構造を持つコアテーブル設計（PostgreSQL）。

-- 1. L3購買・支出取引トランザクション
CREATE TABLE l3_transaction_ledger (
    transaction_id       UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    applicant_user_id    VARCHAR(64) NOT NULL,
    department_code      VARCHAR(32) NOT NULL,
    approver_chain_json  JSONB NOT NULL,
    sku_code             VARCHAR(128),
    item_name            TEXT NOT NULL,
    unit_price           NUMERIC(12, 2) NOT NULL,
    quantity             INT NOT NULL DEFAULT 1,
    tax_rate_type        VARCHAR(16) CHECK (tax_rate_type IN ('STANDARD_10', 'REDUCED_8', 'EXEMPT')),
    requested_at         TIMESTAMP WITH TIME ZONE NOT NULL,
    approved_at          TIMESTAMP WITH TIME ZONE,
    ordered_at           TIMESTAMP WITH TIME ZONE,
    inspected_at         TIMESTAMP WITH TIME ZONE,
    channel_code         VARCHAR(64) NOT NULL,
    supplier_id          VARCHAR(64),
    account_title_code   VARCHAR(32) NOT NULL,
    project_code         VARCHAR(64),
    purpose_statement    TEXT NOT NULL,
    payment_type         VARCHAR(16) CHECK (payment_type IN ('CORPORATE_INVOICE', 'PERSONAL_REIMBURSEMENT')),
    anomaly_flag         BOOLEAN DEFAULT FALSE,
    duplicate_flag       BOOLEAN DEFAULT FALSE,
    created_at           TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP
);

-- 2. 統合資産台帳（個体・数量・親子セット品構造）
CREATE TABLE asset_items (
    asset_id             UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    asset_code           VARCHAR(64) UNIQUE NOT NULL, -- AST-XXXX
    parent_asset_id      UUID REFERENCES asset_items(asset_id), -- 親子セット品バインド
    transaction_id       UUID REFERENCES l3_transaction_ledger(transaction_id),
    asset_type           VARCHAR(16) CHECK (asset_type IN ('FIXED_INDIVIDUAL', 'CONSUMABLE_QUANTITY')),
    asset_name           VARCHAR(255) NOT NULL,
    serial_number        VARCHAR(128),
    stock_quantity       INT DEFAULT 1, -- 消耗品用数量
    min_stock_threshold  INT DEFAULT 0, -- 自動補充閾値
    status               VARCHAR(32) CHECK (status IN ('NORMAL', 'IN_USE', 'REPAIR_NEEDED', 'BROKEN', 'LOST')),
    attached_files_json  JSONB, -- 取扱説明書(PDF)、保証書(画像)等
    created_at           TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP
);

5. 将来拡張ロードマップ（構想・機能メモ）

メモ 01 経費精算機能・AI-OCR拡張構想

既存の経費精算SaaSの前段（上位ハブ）として1approvalを位置づける高機能化ロードマップ。

  • (a) 証票一元紐付け ＆ 経費精算SaaS送出: 各種ワークフローから連携されたデータに領収書・証票を紐付けて一元管理し、接続先の経費精算システム（楽楽精算、Concur等）へ自動送出。
  • (b) 1approval外購入のAI-OCR自動WF構築: 他チャネルで取得した見積書・請求書・領収書データを1approvalサーバーに送信すると、AI-OCRで即座にデータ化。自動的に回覧ワークフローを起案し承認を獲得するロジック。
  • 外貨レート自動計算: 海外出張や外貨建て請求書に対し、取引日時点のTTS為替レートを自動取得・換算計上。
メモ 02 AI Agentic リアルタイム購買レコメンド

ユーザーが購買アクションを起こした瞬間に、AI Agentが介入して最適な購入条件を助言する機能。

  • チェックイン時リアルタイムレコメンド: 各フロントワークフローの買い物かご（カート）をチェックイン（チェックアウト）したタイミングで、1approvalのAI Agentがバックグラウンド起動。
  • 代替案提示: 同等性能のコスト削減アイテム（プライベートブランド、他ECの安値品）や、より納期の早いアイテム、統合購買割引が適用できるSKUをリアルタイムに画面上へポップアップ推薦。
メモ 03 RFP・見積選定（非EC領域TAM拡大）

カタログ型ECサイトでカバーできない「非標準品・工事・受託サービス等」へ購買管理領域（TAM）を拡大するモジュール。

  • サプライヤー群管理 ＆ 相見積もり発行 (RFP): 1approval上に登録された取引先サプライヤー群を選択し、提案依頼書（RFP）や見積依頼を一括送付。
  • 見積回収・比較選定ボード: 各社から返信された見積結果を同一画面でマトリクス比較。最安値・最適条件のサプライヤーをワンクリックで選定し、後続の承認ワークフローへシームレスにデータ接続。

6. 開発戦略

開発優先順位 ＆ 実装ロードマップ（収益化 ✕ 現場定着ハイブリッド） Strategic Roadmap v3.6

「最速の初期MRR創出（可視化＋資産Add-on） ➔ 接続拡張による従量課金積み上げ ➔ エンタープライズ昇格＆高額AI Add-onによるLTV最大化」という、顧客価値（PLG）と収益化（マネタイズ）を完全合致させた最先端ロードマップです。

Phase 1【可視化・現物定着 ＆ 最速MRR回収】(機能 5 → 4 → 6 → 9 → 10)
目標ARPU: ¥230,000 /月

狙い: 手動入力/CSVからでも即座に支出を見せ（5）、予算ブロック（6）でCFO決済を獲得。そのまま資産台帳（9）・スマホ棚卸（10）をセットで提供し、基本料10万＋資産Add-on(8万)＋棚卸Add-on(5万)の月額23万円/社を初月から最速回収する。
