1.1 1approval Core のコンセプト

「あらゆる承認と、それに伴う購買・支出・リソース移動を単一ハブで統合制御する企業の中枢神経系」

1approvalは、企業内に乱立するワークフローシステム（kintone, Garoon, Salesforce等）と各種EC/調達プラットフォーム（MonotaRO, Amazon Business, エイチ, 団タメ等）、法人カード/交通系IC明細、さらには現地立替精算をシームレスに中継します。

通過するデータを標準化されたL3データ（Who / What / When / Where / Why）として蓄積し、Peppol電子請求・インボイス対応の基盤化、全社SaaSへの人事プロビジョニング一括Sync、社内規程RAG AIチャットボット、および自動会計ルーティングを実現します。

2. 中核機能プラットフォーム

中核 01 2.1 Flowbuilder ＆ サプライヤー自動契約オンボーディング

接続先システム同士のフロー設計（Flowbuilder）と、新規購買チャネル開設時のサプライヤー自動契約（デジタル締結）を一元化されたUIで処理します。

1approval Core 中核配置 キャンバス中央に「1approval Core & RAG判定エンジン」を固定配置。左側に各種申請WF（kintone等）、右側に接続先SaaS（モノタロウ, 奉行等）をノード接続。
ノードインスペクター設定 キャンバス上の各SaaSノードをクリックすると「インスペクター（設定パネル）」が開き、APIキー設定、データ同期方向、スキーマ/カラムマッピングルールをGUI上で操作可能。
サプライヤー自動契約 1approval画面上で標準約款への電子同意を行うだけで、相手先ECとのAPI連携ノードが即座にアクティブ化しオンボーディングが完結。
中核 02 2.2 組織・人事Sync ＆ 各種SaaS一括API同期（プロビジョニング）

SmartHRやCSVから取り込んだ全従業員マスターを1approval上でインポート・編集し、連携する全SaaSへ一気に同期します。

  • 全社従業員マスタ管理: 氏名、所属部署、役職、メールアドレス、通勤定期区間（交通IC控除用）、1approval権限を一元管理。
  • 画面上でのリアルタイム修正: 各従業員レコードの「修正」ボタンから属性変更を即座に適用・保存。
  • 全SaaS一括APIプロビジョニング: ボタン一発で修正済みマスターを SmartHR、jinjer、kintone（承認権限マスタ）、モノタロウ/Amazon（購買アカウント）、勘定奉行/楽楽精算（社員コード） へ双方向Sync。
中核 03 2.3 L3 Ledger 蓄積 ＆ 会計・経費仕訳自動ルーティング

全社の購買・支出データの最重要データベースとして、取引を高度なL3データ（Who/What/When/Where/Why）へ正規化保存し、監査アラートと仕訳ルーティングを提供します。

L3要素保持データ項目用途
WHO申請者ID、所属部署、承認者チェーン、予算オーナー監査トレース、費用負担部署特定
WHATSKU明細、品目名、単価、数量、税区分(10%/8%/軽減)デジタルインボイス(Peppol)、仕訳自動化
WHEN申請日、承認完了日、発注日時、検収確認日期末決算処理、未払計上コントロール
WHERE購買チャネル(Amazon/モノタロウ/現地等)、店舗コードチャネル別支出分析、相場比較
WHY勘定科目、プロジェクトコード、申請目的理由予実管理、ガバナンスルールチェック

最重要コントロールハブUI: 上部に「警報サマリー（🔴相場異常 / 🟡重複疑い / 🔵現場未検収）」フィルターを配置し、要確認明細の一括監査・修正リカバリーアクションを実行可能。

中核 04 2.4 統合支出・購買・予実リアルタイム制御

ECサイトでの購買、専門サービスの予約、現地立替経費を同一画面でリアルタイムに見える化し、予算超過を判定します。

  • チャネル統合モニタリング: モノタロウ、Amazon、団タメ、現地立替の消化金額と予算進捗率を可視化。
  • 予算オーバー自動ブロック: 予算配分額を超過した申請が発生した場合、承認プロセスを一時ロックまたは特別役員承認フローへ自動バイパス。
中核 05 2.5 ガバナンス・不正・異常検知エンジン

全支出データに対しAI・ルールベースのモニタリングを実施し、リスクのある申請を自動抽出します。

相場異常値チェック
過去実績や市場平均単価と比較し、一定倍率（例: 5倍以上）を超える割高な購入や不正高額経費を警告。
重複精算チェック
同日・同金額・同一領収書画像（画像ハッシュ照合）による法人カードと現金立替の二重申請を防止。
社内規程逸脱チェック
「新幹線グリーン車利用」「交際費上限オーバー」「事前申請なし事後精算」などの規程違反をフラグ立て。
中核 06 2.6 部署別 ＆ 予算項目別 月次予算分配カレンダー

年度・月ごとに各部署（製造課、営業部、開発部等）へ「間接資材」「出張旅費」「交際費」「ITライセンス費」等の上限予算額をフレキシブルに配分設定します。

  • 12ヶ月配分マトリクスグリッド: 部署×科目×4月〜3月の月次グリッド上で数字を入力・即時調整。
  • 年間消化予測 ＆ 自動合算: 入力された配分額をリアルタイム集計し、全社総予算フレームとの差異を自動表示。
中核 07 2.7 コーポレートカード ＆ 交通系IC・定期自動控除連携

カード明細および交通ICの乗車履歴をAPI自動取り込みし、入力負担をゼロ化します。

コーポレートカード連携 Visa / JCB / Mastercard / Amex等の法人カード利用明細をリアルタイム同期。L3データへ直結させ、立替精算との二重請求を物理遮断。
交通系IC ＆ 経路検索 モバイルSuica / PASMO やICカードリーダーの乗車履歴を自動インポート。「駅すぱあと / ジョルダン」等の経路検索エンジンAPIと接続。
通勤定期区間の自動控除 人事マスタに登録された各社員の「通勤定期区間（例: 品川〜東京）」を照合し、重複する乗車区間運賃（-¥820等）を自動算出して差し引いた適正額のみを精算計上。
中核 08 2.8 社内規程 RAG AIヘルプデスクチャット

自社の旅費規程・購買規程・就業規則（PDF/Word）をアップロードしてベクトルデータベース化し、従業員からの社内ルールの問い合わせにAIが即答します。

  • 右下フローティングチャットUI: 画面右下に常駐するアイコンを押すとスライド表示。「新幹線でグリーン車は使える？」「出張日当はいくら？」に即座に回答。
  • 根拠条文の提示: 回答の根拠となった自社規程の該当ページ（例: 旅費規程 第12条第2項）をリンク提示し信頼性を担保。
  • 管理者用 RAGベクトル学習管理: 管理者画面から新しい規程ドキュメントの追加・再インデックス・学習状態の管理が可能。
中核 09 2.9 レポーティング ＆ 経営・出張・交際費BI

Chart.jsを活用した3視点のビジュアルグラフと出張者スマートトラッカーを提供します。

月次交際費 vs 出張費推移
交際費 税法区分割合 (1万円基準)
部門別 支出比較ランキング

アクティブ出張者トラッカー: 国内外の渡航中社員の滞在先、期間、安全確認状態をリアルタイム表示し、現地駐在員や安否確認システムへ自動連携。

3. 現場・資産運用機能

現場 01 3.1 統合資産台帳（個体・数量・親子セット備品）

検収されたL3購買データからワンタップで資産登録。個体・数量・親子構成管理をサポートします。

個体管理 (Fixed Assets) PC、車両、機器など管理番号（AST-XXXX）やシリアルNoを個別に付与。仕様書・保証書・QR印字に対応。
数量管理 (Consumables) パーツ類・消耗品などの総在庫数を管理。出庫ピックアップで即時減算し、安全在庫未満で自動補充購入フローを発火。
親子セット備品 (Bundle) 「一眼レフカメラ本体（親）」に対し「交換レンズ」「三脚（子）」を親子関係（parent_asset_id）としてバインド管理。一括貸出に対応。
現場 02 3.2 MDM・IT資産 ＆ 契約期限/校正アラート

IT端末（PC、スマホ、タブレット）のスペック情報（OS, CPU, RAM, MACアドレス, IMEI）をMDM（Intune / Jamf Pro）とAPI連携。

  • 契約・校正アラート通知: リース満了日、メーカー保証期限、計測器の校正期限の30日前・60日前に自動アラート配信。校正切れ機器の貸出を自動ブロック。
  • 退職・異動時の遠隔ロック命令: 人事Syncと連動し、退職日をもってMDM経由で遠隔ロック・ワイプを実行。
現場 03 3.3 共有備品 カレンダー型貸出予約 ＆ モバイルPWA実地棚卸
7列×月間カレンダー型 貸出予約UI

測定器・端末・車両などの予約状況をフルカレンダーで確認し、クリック予約。貸出中バッジや返却遅延催促通知を発火。

スマホカメラによる現場リアルタイム棚卸 (PWA)

現場担当者がPWA/スマホカメラでQRコードをスキャンし、状態区分を報告。

  • 状態4区分報告: スキャン時に【正常】【要修理】【破損・故障】【紛失】を選択し、写真付きでリアルタイム報告。
  • オフライン自動同期: 電波の届かない地下倉庫でもローカル保存し、通信復帰時に理論在庫との差分を一括更新。

4. データモデル・API仕様

Data 01 4.1 L3 Ledger ＆ 資産管理データベース構造

L3購買取引データおよび親子バインド資産構造を持つコアテーブル設計（PostgreSQL）。

-- 1. L3購買・支出取引トランザクション
CREATE TABLE l3_transaction_ledger (
    transaction_id       UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    applicant_user_id    VARCHAR(64) NOT NULL,
    department_code      VARCHAR(32) NOT NULL,
    approver_chain_json  JSONB NOT NULL,
    sku_code             VARCHAR(128),
    item_name            TEXT NOT NULL,
    unit_price           NUMERIC(12, 2) NOT NULL,
    quantity             INT NOT NULL DEFAULT 1,
    tax_rate_type        VARCHAR(16) CHECK (tax_rate_type IN ('STANDARD_10', 'REDUCED_8', 'EXEMPT')),
    requested_at         TIMESTAMP WITH TIME ZONE NOT NULL,
    approved_at          TIMESTAMP WITH TIME ZONE,
    ordered_at           TIMESTAMP WITH TIME ZONE,
    inspected_at         TIMESTAMP WITH TIME ZONE,
    channel_code         VARCHAR(64) NOT NULL,
    supplier_id          VARCHAR(64),
    account_title_code   VARCHAR(32) NOT NULL,
    project_code         VARCHAR(64),
    purpose_statement    TEXT NOT NULL,
    payment_type         VARCHAR(16) CHECK (payment_type IN ('CORPORATE_INVOICE', 'PERSONAL_REIMBURSEMENT', 'CORPORATE_CARD')),
    commuter_pass_deduct NUMERIC(10, 2) DEFAULT 0.00, -- 定期自動控除額
    anomaly_flag         BOOLEAN DEFAULT FALSE,
    duplicate_flag       BOOLEAN DEFAULT FALSE,
    created_at           TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP
);

-- 2. 統合資産台帳（個体・数量・親子セット品構造）
CREATE TABLE asset_items (
    asset_id             UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    asset_code           VARCHAR(64) UNIQUE NOT NULL, -- AST-XXXX
    parent_asset_id      UUID REFERENCES asset_items(asset_id), -- 親子セット品バインド
    transaction_id       UUID REFERENCES l3_transaction_ledger(transaction_id),
    asset_type           VARCHAR(16) CHECK (asset_type IN ('FIXED_INDIVIDUAL', 'CONSUMABLE_QUANTITY')),
    asset_name           VARCHAR(255) NOT NULL,
    serial_number        VARCHAR(128),
    stock_quantity       INT DEFAULT 1,
    min_stock_threshold  INT DEFAULT 0,
    status               VARCHAR(32) CHECK (status IN ('NORMAL', 'IN_USE', 'REPAIR_NEEDED', 'BROKEN', 'LOST')),
    attached_files_json  JSONB,
    created_at           TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP
);

5. 将来拡張ロードマップ（構想・機能メモ）

メモ 01 経費精算機能・AI-OCR自動起案拡張

既存の経費精算SaaSの前段（上位ハブ）として位置づける高機能化ロードマップ。

  • 他チャネル領収書のAI-OCR自動WF起案: 見積書・請求書・領収書画像を送信するとAI-OCRで即座にデータ化。自動的に回覧ワークフローを起案。
  • 外貨レート自動計算: 海外出張や外貨建て請求書に対し、取引日時点のTTS為替レートを自動取得・換算計上。
メモ 02 AI Agentic リアルタイム購買レコメンド

ユーザーが購買アクションを起こした瞬間に、AI Agentが介入して最適な購入条件を助言する機能。

  • チェックイン時リアルタイムレコメンド: カートチェックインのタイミングでAIがバックグラウンド起動。同等性能のコスト削減品（PB品等）や納期の早い代替品をポップアップ提案。
メモ 03 RFP・相見積もり選定ボード (TAM拡大)

カタログ型ECサイトでカバーできない「非標準品・特注品・工事・受託サービス等」へ購買管理領域（TAM）を拡大するモジュール。

  • RFP一括発行 ＆ 3社比較マトリクス: サプライヤー群へ見積依頼（RFP）を一括送付。回収した見積結果を同一画面で比較選定し、後続承認WFへシームレス接続。

6. 開発戦略

開発優先順位 ＆ 実装ロードマップ（【収益 ✕ 現場定着】ハイブリッド設計） Strategic Hybrid Roadmap v4.0

過去の思考である「現場UX・定着重視のPLG順序」に、「最速マネタイズ（初期MRR最大化＆高単価化）」の観点を融合させたハイブリッド開発ロードマップです。初月から「基本料＋資産＋棚卸 Add-on」のクロスセルを達成し、段階的に積み上げ従量収入とエンタープライズ昇格（年商1,000万超アカウント）を狙います。

Phase 1【可視化 ＆ 現場定着 ＋ 最速マネタイズ】(機能 2.4, 2.6 ➔ 2.3 ➔ 3.1 ➔ 3.3)
目標ARPU: 月額 23万円

狙い: 手動CSVからでも支出を即座に可視化し、そのまま現場の「資産台帳・棚卸・カレンダー貸出」へ繋げて定着させつつ、初月から基本料＋Add-onで最速マネタイズを達成。

  • 2.4 / 2.6 支出ダッシュボード ＆ 予算分配カレンダー: 支出全体像と部署別予算枠の可視化
  • 2.3 L3 Ledger 蓄積 ＆ 仕訳ルーティング: データ正規化DB ＆ 監査アラートハブUI
  • 3.1 / 3.2 統合資産＋MDM IT台帳 ＆ 期限/校正アラート: 購買データからの自動台帳化・期限通知
  • 3.3 貸出予約カレンダー ＆ スマホカメラPWA実地棚卸: 現場のQRスキャン報告・7列カレンダー
Phase 2【自動中継ハブ化 ＆ 積み上げ従量課金拡大】(機能 2.9 ➔ 2.1 ➔ 2.7)
目標ARPU: 月額 35〜40万円

狙い: 蓄積されたデータの経営BIを提供しつつ、外部SaaSやカード/交通ICとの接続を拡張。接続数追加（+2万円/社）の積み上げ従量収入を加速。

  • 2.9 レポーティング ＆ 経営・出張・交際費BI: 損金上限枠・税法区分・出張者トラッカー
  • 2.1 Flowbuilder ＆ サプライヤー自動契約: 中核1approval接続 ＆ ノードインスペクター設定
  • 2.7 法人カード ＆ 交通系IC・定期自動控除: 乗車履歴自動同期 ＆ 定期区間マイナス控除
Phase 3【エンタープライズ昇格 ＆ LTV最大化】(機能 2.2 ➔ 2.5 ➔ 2.8 ＋ メモ1〜3)
目標ARPU: 月額 60〜100万円超

狙い: 全社SaaSプロビジョニングでEnterpriseプラン（30万円）へ昇格させ、ガバナンスAI・社内規程RAG等の高額Add-onを被せて年間1,000万円超アカウントへ成長させる。

  • 2.2 人事Sync ＆ 各種SaaS一括プロビジョニング: 従業員マスタ編集 ＆ 5大SaaS一括API同期
  • 2.5 ガバナンス・不正・異常検知エンジン: 相場異常・重複精算・規程外AI検知
  • 2.8 社内規程 RAG AIヘルプデスクチャット: 規程ベクトルDB化 ＆ 右下常駐チャットbot
  • メモ1-3 AI-OCR自動起案 / AI Agentic購買レコメンド / RFP相見積選定ボード

③ 機能モジュール Add-on
資産MDM、棚卸、ガバナンスAI、社内規程RAG、RFP等の高付加価値単体課金
